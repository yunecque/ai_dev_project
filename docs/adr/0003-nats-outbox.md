# ADR-0003: NATS JetStream + transactional outbox

- **Статус:** accepted
- **Дата:** 2026-09-21
- **Контекст:** Доменное событие `RequestCreated` должно быть опубликовано надёжно и ровно
  один раз обработано, без распределённых транзакций и без dual-write между БД и брокером.
- **Решение:** заявка и outbox-запись пишутся в **одной PostgreSQL-транзакции**; отдельный
  publisher доставляет события в NATS JetStream; worker обрабатывает идемпотентно.
- **Обоснование:** transactional outbox исключает потерю/фантомную публикацию события при
  сбое. JetStream даёт at-least-once + persistence; идемпотентность consumer'а закрывает
  дубликаты.
- **Последствия:** нужна таблица outbox, publisher-процесс, дедупликация по event id,
  наблюдаемость лага публикации.
- **Ссылки:** конституция §2, §6; ADR-0010.
